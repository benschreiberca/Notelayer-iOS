### 2c. ⚠️ Build number when building via GitHub Actions / fastlane
File: `fastlane/Fastfile` lines 66–88.

CI **overrides** `CURRENT_PROJECT_VERSION` at build time with `GITHUB_RUN_NUMBER` (via
`increment_build_number`). So:
- **Manual Xcode archive** → build number = `2` (what's committed). ✅ fine, `2 > 1`.
- **CI build** → build number = the GitHub Actions run number. This is monotonic, so it will
  be `> 1`, but it will **not** be `2`. That's fine for App Store Connect (any number `> 1`
  for version 1.5.0 is accepted). Just confirm the run number that ends up on the build is
  greater than `1`.

**Hard rule:** the uploaded build's number must be **strictly greater than 1** for version
`1.5.0`. Previous upload was `1.5.0 (1)`.
