Executive Summary

What: A Manifest V3 Chrome extension popup (300×400px) that lets users capture tasks while browsing, without reaching for their phone.

Why now:

  • iOS v1.5.0 shipped with simpler, focused UX (two-tab navigation, no experimental gates)
  • Backend (Firebase/Firestore) is stable and multi-platform ready
  • Browser capture is the #2 most-requested feature
  • Chrome extension market is high-growth for productivity tools

Success looks like: 200+ installs in first month, 60%+ return user rate, 5–10 tasks per user per day.

Value Proposition

For Existing Notelayer Users: Capture tasks from your browser without reaching for your phone. No friction, no context switch.
For New Users: Try Notelayer on desktop before committing to the iOS app. Same Firebase account, instant sync across devices.
For High-Volume Capturers: Add 20–30 tasks per day with one-click category and priority tagging.
For the Product: Expands Notelayer into a high-intent context (web browsing) and enables future desktop (macOS) and wearable (Watch) expansion.

Core Functions

Authentication

Allow users to sign in with email/password or Google account. Token stored securely in browser storage. Auto-refresh before expiration.

Task Capture

Text field accepts 1–200 character task description. Direct write to Firestore (same database as iOS app). Show success/error feedback.

Category Selection

Dropdown loads user's categories from Firestore. "Uncategorized" as fallback. Selector remembers last choice for rapid-fire adding.

Priority Assignment

Four-button toggle (Low / Medium / High / Urgent). Default: Medium. Preference persisted for next session.

Theme Management

Detect system dark/light preference on open. Allow manual toggle. Use iOS app's accent color from user's theme settings.

Session Management

Sign out link clears token and shows auth screen on next open. Account settings managed via iOS app or Firebase console (not in extension).

Why This Split?

MVP1 (v1.5) Focus: Single responsibility — capture, nothing else. Popup with text field + category + priority + save. Minimal scope, maximum reliability.

MVP2 (v1.6) Expansion: Power user features. Context menu, keyboard shortcuts, offline support, editing. Builds on stable MVP1 foundation.

MVP2+ (v1.7) Vision: Full-featured desktop task manager via Chrome Side Panel. Separate project, but built on same Firebase backend.

Analytics Instrumentation

Add metadata to every task written by extension:

{
  "taskId": "uuid",
  "title": "...",
  "categories": ["cat-id"],
  "priority": 1,
  "completed": false,
  "createdAt": timestamp,
  "createdFrom": "chrome-extension",
  "authMethod": "email" | "google",
  "theme": "light" | "dark"
}

No third-party analytics: Chrome Web Store policies restrict trackers in privacy-focused products. Use Firestore metadata + Chrome Web Store built-in analytics only.

Technical Specifications

Architecture

manifest.json popup/ popup.html (UI skeleton) popup.css (Styling) popup.js (UI logic) auth/ auth.js (Firebase auth setup) oauth.html (Google OAuth redirect) firebase/ config.js (API keys, setup) firestore.js (Task CRUD) sync.js (Token refresh) storage/ local-storage.js (chrome.storage wrapper) cache.js (Category cache) icons/ icon-16.png icon-48.png icon-128.png background.js (Service worker)

Technology Stack

Layer Technology Why
Manifest Manifest V3 Required by Chrome; V2 deprecated
UI HTML/CSS/JS (vanilla) Lightweight, no build step, small bundle
Auth Firebase JS SDK v9 Modular, tree-shakeable, same as iOS
Database Firestore (shared with iOS) No backend work; same data model
Storage chrome.storage.local Persistent, secure, browser-managed

File Size Target

< 500 KB (zipped)

  • Firebase JS SDK v9 + auth: ~200 KB
  • HTML/CSS/JS logic: ~50 KB
  • Icons + assets: ~20 KB
  • Overhead: ~30 KB

Security

Authentication & Authorization

  • Firebase token stored in chrome.storage.local (sandboxed)
  • Token lifetime: 1 hour; auto-refresh before expiration
  • Google OAuth via chrome.identity.launchWebAuthFlow() (secure browser-mediated)
  • All communication over HTTPS

Data Privacy

  • No page content captured (no browsing history)
  • No keystroke patterns, timing data, or cross-site tracking
  • All data written to user's own Firestore (not a separate database)
  • Encryption in transit (HTTPS) and at rest (Firestore)

Permissions

{
  "permissions": [
    "storage",              // chrome.storage.local
    "identity"              // Google OAuth
  ],
  "host_permissions": [
    "https://firestore.googleapis.com/*"
  ]
}

Firestore Collections

  • tasks — new tasks written by extension
  • users/{userId}/categories — load user's categories for dropdown
  • users/{userId} — load theme accent color

No new Firestore rules needed. Existing rules already allow authenticated writes.

Known Risks & Mitigations

Firebase auth in Chrome MV3 is finicky
Mitigation: Thorough testing on macOS, Windows, Linux. Test both email/password and Google OAuth. Have fallback flow if one method fails.
Chrome Web Store review might reject for unclear reason
Mitigation: Ensure single purpose ("Task capture"), privacy policy linked, no deceptive content, no permissions without justification.
Users without iOS app don't understand onboarding
Mitigation: In popup, show clear CTA: "Sign up or log in to get started." Link to Notelayer website in privacy section.
Category list is stale if user adds categories in iOS app while extension is open
Mitigation: Refresh category list on every popup open. Document that new categories appear on next extension open.
